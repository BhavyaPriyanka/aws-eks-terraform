For the LocalHelp application, I provisioned the AWS infrastructure using Terraform and deployed the application platform on Amazon EKS. 
I integrated EKS with the existing VPC and private subnets and configured managed node groups separately for frontend and backend workloads. I enabled the required EKS add-ons for DNS, networking, service routing, pod identity, and EBS persistent storage.  
For operational automation, I configured Cluster Autoscaler with IAM-based authentication so node capacity can automatically adjust based on workload requirements. I also configured the AWS Load Balancer Controller with appropriate IAM permissions so Kubernetes can manage AWS load-balancing resources.  
For administration, I used a bastion host with IAM permissions and EKS access entries for cluster authorization.  
For monitoring, I extended the same Terraform-based infrastructure and deployed kube-prometheus-stack through Helm. This provides Prometheus for metric collection and storage, Grafana for visualization, Alertmanager for alert routing, Node Exporter for node-level metrics, and kube-state-metrics for Kubernetes object-state metrics. Prometheus, Grafana, and Alertmanager use persistent EBS-backed storage.  
The overall approach is infrastructure as code: Terraform provisions the AWS and Kubernetes infrastructure, while Helm manages the monitoring application stack in a repeatable and version-controlled way
